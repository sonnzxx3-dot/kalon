## 1. Что уже готово

В проекте `kalon-project/` лежит полностью рабочее приложение:

- Дневник питания (завтрак / обед / ужин / перекус) с кольцом калорий и БЖУ
- Поиск продуктов в базе **Open Food Facts** (миллионы товаров)
- **Своя база продуктов** — пользователь создаёт продукты, вписывает калории и БЖУ вручную, они сохраняются и переиспользуются
- Сканер штрих-кодов (камера + ручной ввод кода)
- Заготовка **анализа еды по фото** (демо-режим; под реальный AI нужен ключ — см. раздел 6)
- Графики: калории по дням, БЖУ, вес тела за месяц
- Расчёт нормы калорий по формуле Миффлина-Сан Жеора
- Сохранение всех данных между запусками (через localStorage в собранном приложении)

Дизайн переделан: тёмная тема «обсидиан + клинок», фирменные цвета плазменно-голубой и фиолетовый, острая геометрия — под бренд Synax Sword AI.

## 2. Главное про APK — честно

Готовый файл `.apk` нельзя «выдать» текстом — его нужно **собрать** из проекта на машине с Android-инструментами. Хорошая новость: проект уже настроен под **Capacitor**, который превращает веб-приложение в настоящее нативное Android-приложение с доступом к камере. Тебе остаётся выполнить несколько команд.

Есть два пути сборки. Выбери тот, что подходит.

### Путь А — на своём компьютере (нужен один раз настроить)

Требуется: Node.js, JDK 17, Android Studio (он ставит Android SDK).

```bash
# 1. Распакуй kalon-project и зайди в папку
cd kalon-project

# 2. Установи зависимости
npm install

# 3. Добавь Android-платформу
npx cap add android

# 4. Синхронизируй веб-код в нативный проект
npx cap sync

# 5. Открой проект в Android Studio
npx cap open android
```

Дальше в Android Studio:
- Подключи телефон по USB (или эмулятор) → кнопка **Run** → приложение установится и запустится. Камера и сканер заработают.
- Для файла, который можно отправить друзьям: меню **Build → Build Bundle(s)/APK(s) → Build APK(s)**. Готовый `app-debug.apk` появится в `android/app/build/outputs/apk/debug/`.

### Путь Б — облачная сборка без установки тяжёлых программ

Если не хочешь ставить Android Studio, используй облачный сборщик. Самый простой вариант — **GitHub Actions**: загружаешь проект в репозиторий, и сборка APK идёт на серверах GitHub бесплатно.

Я подготовил готовый workflow-файл — он лежит в проекте как `.github/workflows/build-apk.yml`. Алгоритм:
1. Создай репозиторий на GitHub, залей туда содержимое `kalon-project`.
2. GitHub автоматически соберёт `app-debug.apk` при каждом пуше.
3. Скачай APK из вкладки **Actions → последняя сборка → Artifacts**.

> Альтернатива для совсем без кода: сервисы вроде **PWABuilder** (pwabuilder.com) умеют принять веб-приложение и выдать Android-пакет почти в один клик. Это самый быстрый способ получить файл, но меньше контроля над настройками.

## 3. Публикация в Google Play — пошагово

### Шаг 1. Аккаунт разработчика
- Зарегистрируйся на **play.google.com/console**.
- Стоимость — **разовый платёж $25** (никакой ежегодной платы нет).
- Тип аккаунта:
  - **Personal** — проще, но требует провести закрытый тест с **12 тестировщиками минимум 14 дней**, прежде чем приложение пустят в открытый доступ. Это правило Google для новых персональных аккаунтов.
  - **Organization** — для компании (Synax Sword AI), требует **D-U-N-S номер** (бесплатный идентификатор организации, оформляется несколько дней-недель). Без 12 тестировщиков, но больше документов.

> Для бренда Synax Sword AI логичнее Organization-аккаунт, но если хочешь запуститься быстро — начни с Personal.

### Шаг 2. Технические требования (актуально на 2026)
- Для загрузки в Google Play нужен формат **AAB** (Android App Bundle), не APK. Capacitor/Android Studio собирают и то, и другое.
- **С 31 августа 2026 года новые приложения должны таргетировать Android 16 (API level 36) или выше.** Проверь в `android/app/build.gradle`, что `targetSdkVersion` = 36. До этой даты допустим и 35, но лучше сразу ставить 36.
- Приложение нужно **подписать** релизным ключом (keystore). В Android Studio: **Build → Generate Signed Bundle/APK → создать keystore → сохрани его и пароль навсегда** (без него не сможешь обновлять приложение).

### Шаг 3. Карточка в Play Console
Подготовь заранее:
- Иконку 512×512 (могу сгенерировать дизайн)
- Скриншоты (минимум 2, телефон)
- Краткое и полное описание
- Политику конфиденциальности (обязательна, особенно раз есть камера) — простую страницу можно разместить на бесплатном хостинге
- Заполнить раздел **Data Safety** (какие данные собираются; у тебя всё хранится локально — это плюс)

### Шаг 4. Загрузка и проверка
- Загрузи AAB во вкладку **Production** (или сначала **Testing**).
- Первая модерация занимает обычно от нескольких часов до нескольких дней.

## 5. Как на этом заработать

**Твоя выбранная модель: реклама + платное отключение.** Описываю её подробно как основную, остальные — как дополнения на будущее.

### Основная модель — реклама + платное отключение

Приложение бесплатное и показывает рекламу. Пользователь может один раз заплатить (или оформить подписку), чтобы рекламу убрать. В приложении это уже реализовано на уровне интерфейса: внизу есть рекламный баннер-плейсхолдер, а в разделе **Kalon Premium → Убрать рекламу** работает переключатель (демо-покупка). Осталось заменить плейсхолдер на настоящую рекламу и подключить настоящую оплату при сборке (см. раздел 5.1).

Как лучше выстроить:
- **Баннер** внизу экрана — самый мягкий формат, не мешает пользоваться дневником. Он уже встроен в макет.
- **Межстраничную (полноэкранную) рекламу** показывай редко и по событию — например, раз в несколько добавлений еды, а не на каждом шаге. Агрессивная реклама в фитнес-приложении убивает удержание.
- **«Убрать рекламу»** сделай разовой покупкой (например, 299-499 ₽) — это понятнее пользователю, чем подписка, и хорошо конвертит. Подписку можно добавить позже.
- Никогда не показывай рекламу поверх ввода данных или результатов — только в «паузах».

Доход здесь складывается из двух потоков: мелкие, но постоянные деньги с рекламы (зависит от числа активных пользователей) и разовые покупки отключения от самых вовлечённых.

### 5.1. Как подключить настоящую рекламу и покупку (при сборке)

Это работает **только в собранном APK**, не в превью. В проект уже добавлены нужные плагины в `package.json`:
- `@capacitor-community/admob` — баннеры и межстраничная реклама Google AdMob
- `@capgo/capacitor-purchases` — внутриигровые покупки (отключение рекламы)

Порядок действий:

1. **Заведи аккаунт AdMob** (admob.google.com), создай приложение и рекламный блок-баннер. Получишь App ID и Ad Unit ID.
2. **Свяжи AdMob с приложением.** App ID прописывается в `android/app/src/main/AndroidManifest.xml`.
3. **Покажи баннер в коде.** Вместо плейсхолдера в `index.html` (блок `id="adBanner"`) вызывается плагин — примерная схема:

```js
import { AdMob, BannerAdPosition, BannerAdSize } from '@capacitor-community/admob';

await AdMob.initialize();
await AdMob.showBanner({
  adId: 'ВАШ_AD_UNIT_ID',
  adSize: BannerAdSize.BANNER,
  position: BannerAdPosition.BOTTOM_CENTER,
});
// когда куплено отключение:
await AdMob.removeBanner();
```

4. **Покупка отключения.** В Google Play Console создай товар In-app product (например `remove_ads`). В коде кнопка «Убрать рекламу» вызывает покупку через плагин purchases; после успешной покупки выставляешь `S.premium = true` (этот флаг уже управляет показом баннера в приложении) и сохраняешь его.

> Важно: и AdMob, и покупки требуют, чтобы приложение было собрано и (для теста покупок) загружено хотя бы в закрытый тест Google Play. В вебе и в эмуляторе без настройки они не работают — это нормально.

### Дополнительные модели (на потом)

- **Разовые покупки функций** — «PDF-отчёт для тренера», наборы тем, пакеты фото-анализа.
- **Freemium-подписка** — когда добавишь фото-AI, его логично сделать платной функцией, чтобы покрыть расходы на API.
- **B2B** — версия для тренеров и нутрициологов, которые ведут клиентов.

### С чего реально начать

1. Запусти бесплатное приложение с **баннером** и кнопкой «Убрать рекламу».
2. Собери первых пользователей и отзывы, посмотри удержание.
3. Когда аудитория подрастёт — аккуратно добавь межстраничную рекламу и/или подписку.

> Реклама даёт ощутимый доход только на объёме (тысячи активных пользователей). Поэтому на старте главное — не выручка с баннера, а удобство и удержание: чем дольше люди пользуются, тем больше и рекламного дохода, и покупок отключения.

## 6. Анализ еды по фото — как сделать по-настоящему

Сейчас в приложении это **демо**: показывает заглушку-результат. Чтобы заработало реально, нужно три вещи:

1. **Vision-AI модель.** Отправляешь фото блюда → модель возвращает название и оценку калорий/БЖУ. Подходят Anthropic Claude (vision), OpenAI GPT-4o и аналоги.
2. **Свой backend-сервер.** API-ключ **нельзя** держать внутри приложения (его вытащат и потратят твои деньги). Поэтому: приложение → твой сервер → AI-API → обратно. Сервер прячет ключ и считает лимиты пользователей.
3. **Бюджет.** Каждый запрос платный. Поэтому функция — в Premium.

В коде приложения уже размечено место под реальный запрос — ищи комментарий `=== МЕСТО ДЛЯ РЕАЛЬНОГО AI-ЗАПРОСА ===` в функции `handlePhoto`. Минимальная схема серверного эндпоинта:

```
POST /analyze-food
  тело: { image: "<base64>" }
  сервер вызывает vision-модель с промптом:
    "Определи блюдо на фото. Верни ТОЛЬКО JSON:
     {name, cal, prot, fat, carb} — значения на 100 г, оценочно."
  ответ приложению: { name, cal, prot, fat, carb }
```

> Точность оценки по фото ограничена: модель не знает точный вес и состав, поэтому подаём результат как **примерную оценку**, которую пользователь может поправить (в приложении эта возможность уже есть — кнопка «Поправить значения вручную»).
