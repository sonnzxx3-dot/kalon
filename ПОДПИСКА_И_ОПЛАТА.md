# Kalon · Подписка и оплата — как довести до реальной

Руководство по трём вещам, которые ты просил: оплата подписки 359 ₽ через Google Play, сохранение подписки без регистрации, и где это «включается».

---

## Коротко: что уже сделано в приложении

- Красивый экран подписки (paywall) с тарифами **359 ₽/мес** и годовым со скидкой.
- Кнопка **«Восстановить покупку»** — для переноса подписки на новое устройство без регистрации.
- Рекламный баннер, который автоматически исчезает, когда Premium активен.
- В коде размечены места, где подключается реальная оплата (комментарии `=== ПОКУПКА ===` и `=== ВОССТАНОВЛЕНИЕ ===` в `www/index.html`).

Сейчас это **демо**: нажатие «Подключить» сразу выдаёт Premium, без реальных денег. Ниже — как сделать оплату настоящей.

---

## Важно понять: почему оплату нельзя «просто включить»

Настоящие платежи в Android-приложениях идут **только через Google Play Billing** — это требование Google, обойти его нельзя (свой приём карт внутри приложения для цифровых товаров запрещён правилами Play). А Google Play Billing работает при двух условиях:

1. Приложение **загружено в Google Play** (хотя бы в закрытый тест).
2. В Play Console **создан товар-подписка** с ценой.

Поэтому маршрут такой: сначала публикация → потом подписка оживает. До публикации она физически остаётся в демо-режиме. Это нормально и правильно.

---

## Пункт 2 — подписка без регистрации (это уже решено)

Тебе **не нужны** логины, пароли и сервер с базой пользователей. Вот почему:

Google Play **сам** привязывает покупку к Google-аккаунту пользователя. Когда человек платит за подписку, Google это запоминает на стороне аккаунта. Дальше:

- На том же телефоне подписка видна всегда.
- На новом телефоне человек заходит под тем же Google-аккаунтом, открывает Kalon, нажимает **«Восстановить покупку»** — приложение спрашивает у Google «есть ли активная подписка у этого аккаунта?», получает «да» и включает Premium.

Это называется **restore / queryPurchases** и встроено в Google Play Billing. Никакой твоей регистрации не требуется — за «учёт пользователей» отвечает Google. Кнопка «Восстановить покупку» в приложении уже есть, её нужно лишь подключить к реальному плагину (ниже).

> Когда регистрация всё же нужна: только если захочешь синхронизировать **сам дневник питания** между устройствами (еда, вес). Это отдельная большая задача с сервером. Для подписки — не нужна. На старте дневник хранится локально на телефоне, и это нормально.

## Пункт 1 — как сделать оплату 359 ₽ настоящей

### Шаг 1. Создай подписку в Google Play Console

1. Опубликуй приложение хотя бы в закрытый тест (см. основное руководство, раздел 3).
2. В Play Console открой приложение → **Monetize → Products → Subscriptions**.
3. Создай подписку:
   - **Product ID**: `kalon_premium_monthly` (запомни — он используется в коде)
   - Название: «Kalon Premium (месяц)»
   - Базовый план: автопродление, период — 1 месяц
   - Цена: **359 ₽** (Google поможет проставить цены для других стран)
4. (Опционально) Создай вторую подписку `kalon_premium_yearly` на год за 2 990 ₽.
5. Активируй подписки.

### Шаг 2. Подключи плагин биллинга в проекте

Для Capacitor самый надёжный вариант — плагин **RevenueCat** (`@revenuecat/purchases-capacitor`) или нативный `@capacitor-community/in-app-purchases`. RevenueCat проще: он берёт на себя проверку покупок и восстановление, бесплатен до приличного оборота.

Установка (локально или допиши в `package.json`):
```bash
npm install @revenuecat/purchases-capacitor
npx cap sync
```

### Шаг 3. Замени демо-функции на реальные вызовы

В файле `www/index.html` найди функции `buyPremium` и `restorePurchase`. Сейчас они демо. Реальная схема (через RevenueCat) выглядит так:

```js
import { Purchases } from '@revenuecat/purchases-capacitor';

// при старте приложения один раз:
await Purchases.configure({ apiKey: 'ВАШ_REVENUECAT_KEY' });

async function buyPremium(plan){
  const id = plan === 'yearly' ? 'kalon_premium_yearly' : 'kalon_premium_monthly';
  try{
    const offerings = await Purchases.getOfferings();
    const pkg = offerings.current.availablePackages.find(p => p.product.identifier === id);
    const { customerInfo } = await Purchases.purchasePackage({ aPackage: pkg });
    if(customerInfo.entitlements.active['premium']){
      S.premium = true; saveSettings(); fillSettings(); closeSheet();
      toast('Premium активирован ✓');
    }
  }catch(e){ toast('Покупка отменена'); }
}

async function restorePurchase(){
  const customerInfo = await Purchases.restorePurchases();
  if(customerInfo.entitlements.active['premium']){
    S.premium = true; saveSettings(); fillSettings();
    toast('Подписка восстановлена ✓');
  }else{
    toast('Активных покупок не найдено');
  }
}
```

Логика остального приложения менять не нужно — флаг `S.premium` уже управляет и баннером, и статусом. Тебе достаточно, чтобы реальная покупка выставляла его в `true`.

### Шаг 4. Тестирование покупок

- Покупки тестируются **только в собранном приложении, загруженном в Play** (трек тестирования).
- В Play Console добавь себя в **License testers** (Setup → License testing) — тогда тестовые покупки не списывают реальные деньги.
- Проверь полный цикл: купить → Premium включился → переустановить → «Восстановить покупку» → Premium вернулся.

## Реклама (AdMob) — связка с подпиской

Баннер в приложении уже скрывается при `S.premium === true`. Чтобы подключить настоящий AdMob:

1. Заведи аккаунт на admob.google.com, создай баннерный блок → получишь Ad Unit ID.
2. Установи плагин: `npm install @capacitor-community/admob`
3. Показывай баннер при старте, если `!S.premium`; вызывай `AdMob.removeBanner()` после покупки.

Пример уже описан в основном руководстве (раздел 5.1).
