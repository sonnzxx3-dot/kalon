# Сборка подписанного AAB через GitHub Actions

Этот документ — пошаговая инструкция, как собрать AAB для Google Play **в облаке GitHub**, без терминала и Android Studio.

## Что у нас уже есть

- Файл ключа подписи **`kalon-keystore.jks`** (на твоём компьютере, в папке `C:\Users\SynaX Sword\kalon-project\android\`).
- Пароль ключа (его ты знаешь — `300502`).
- Workflow `build-apk.yml` уже умеет собирать подписанный AAB, если найдёт ключ в GitHub-секретах.

## Что нужно сделать (один раз)

### Шаг 1. Преобразуй keystore в Base64

Файл ключа — бинарный, в секрет GitHub его кладут в виде текста Base64. Открой PowerShell на твоём компьютере и выполни:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\Users\SynaX Sword\kalon-project\android\kalon-keystore.jks")) | Set-Clipboard
```

Эта команда читает файл ключа и кладёт его текстовое представление **в буфер обмена**. На экране ничего не появится — это нормально.

### Шаг 2. Добавь 4 секрета в репозиторий GitHub

1. Зайди в свой репозиторий **kalon** на GitHub.
2. Сверху открой **Settings** (Настройки).
3. В левом меню: **Secrets and variables → Actions**.
4. Нажми зелёную кнопку **New repository secret**.

Создай **четыре** секрета (каждый отдельной кнопкой):

| Name (имя) | Secret (значение) |
|---|---|
| `KEYSTORE_BASE64` | вставь из буфера обмена (то, что сгенерировала команда в Шаге 1) |
| `KEYSTORE_PASSWORD` | `300502` |
| `KEY_ALIAS` | `kalon` |
| `KEY_PASSWORD` | `300502` |

После добавления каждого секрета жми **Add secret**.

> Секреты в GitHub зашифрованы и видны только при сборке — никто, включая тебя, не сможет посмотреть их значения после сохранения. Это безопасно.

### Шаг 3. Обнови файлы проекта в репозитории

Если в репозитории `kalon-project/` лежит старая версия — замени **`.github/workflows/build-apk.yml`** на новый из этого архива. Остальные файлы можно не трогать, но безопаснее перезалить весь архив целиком.

### Шаг 4. Запусти сборку

1. На GitHub перейди во вкладку **Actions**.
2. Слева кликни **Build Kalon AAB**.
3. Справа жми **Run workflow → main → Run workflow**.
4. Через 3-5 минут увидишь зелёную галочку.

### Шаг 5. Скачай AAB

Открой завершённую сборку → внизу страницы **Artifacts** → файл **kalon-release-aab**. Скачается ZIP, внутри — `app-release.aab`. Это и есть файл для Google Play.

## Что делает workflow автоматически

Чтобы ты понимал, что происходит:

1. Получает код из репозитория.
2. Устанавливает Node.js, Java 17, Android SDK.
3. Запускает `npm install` и `npx cap add android` (создаёт нативный Android-проект).
4. **Правит `variables.gradle`** — поднимает `targetSdk` и `compileSdk` до 35 (требование Google Play на 2026 год).
5. Кладёт иконку в проект и генерирует все размеры через `@capacitor/assets`.
6. **Восстанавливает keystore** из секрета `KEYSTORE_BASE64`.
7. Запускает `./gradlew bundleRelease` с подписью.
8. Заодно собирает debug-APK для тестов на телефоне.
9. Выгружает оба файла в Artifacts.

---

## Если что-то пойдёт не так

- **Сборка прошла, но AAB нет в Artifacts** — значит секреты не подключились. Проверь, что все 4 секрета созданы, имена точные (с подчёркиваниями), без лишних пробелов.
- **Сборка упала на шаге Build signed AAB с ошибкой про подпись** — скорее всего неправильно сохранён `KEYSTORE_BASE64` (может, обрезалось при копировании). Перезапиши секрет, выполнив команду из Шага 1 ещё раз.
- **Google Play всё ещё ругается на targetSdk 34 после загрузки** — значит сборка прошла на старых файлах. Проверь в логе шаг «Fix targetSdk to 35» — там должно быть видно, как `variables.gradle` правится.

---

## Что дальше после получения AAB

1. Скачай `app-release.aab` из Artifacts.
2. В Google Play Console → Закрытое тестирование → создай новый выпуск → загрузи этот AAB.
3. Все 3 ошибки про отсутствие App Bundle исчезнут.
4. Сохрани выпуск, начни внедрение.
